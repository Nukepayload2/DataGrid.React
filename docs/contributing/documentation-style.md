# 文档风格

data-grid 的文档按“长期可读”组织，不再把任务编号、批次记录和返工过程保留在正文里。

## 总原则

- 写功能、设计原因、已知边界，不写会话进度。
- 文档标题按功能命名，不按字母批次、任务批次或文件所有权命名。
- 重要设计取舍进入 [`../decisions/`](../decisions)，不要只留在某个 demo 注释里。

## 功能文档写什么

每篇功能文档优先回答三件事:

1. 这个能力对外表现是什么
2. data-grid 为什么这样实现
3. 与 antd 或原生表格相比，哪里需要特别注意

## 源码注释迁移规则

- 源码里只保留短注释，说明局部特殊情况即可。
- 复杂推导、兼容差异、踩坑原因移到对应 `docs/features/**`。
- 注释里不要继续保留任务号、决策号、批次名或交接路径清单。

推荐格式:

```ts
// 简短标题 - 详见 docs/features/<domain>/<topic>.md
```

## 文档落点

- 架构层面的长期说明: `architecture/`
- 关键设计取舍: `decisions/`
- 功能行为和实现边界: `features/`
- 兼容矩阵、命名空间和限制清单: `reference/`
- 写作和验证规范: `contributing/`

## 不再保留的内容

- 任务拆批、进度状态、交接清单
- “之前是 X 现在改成 Y” 的历史叙事
- 与当前代码不符的旧实现描述
- 为 agent 流程写的调度说明

## 一事实一处

适用于 `docs/**` markdown 与 docs 站点页面（`src/docs/**`）。

每条事实（语义、字段、边界、迁移动作、能力主张）只在它的**正典页**写全一次。其它页面只允许「一句结论 + 链接」，不重述理由、不复制代码块、不重列 prop 清单。

页面角色决定落点，不由作者偏好决定：

- 入门页：只负责“选路径”，不教 API 细节。
- 功能页：只负责“怎么做”。
- 参考页：只负责“查字段”。
- 选型页：只负责“值不值得迁”。

判断某页是否该写某条事实，先问“这页的角色需要它全文，还是只需要结论”。

### 正典落点

| 事实 | 正典页 |
|------|--------|
| `scroll.y` 语义、滚动分层、父容器高度责任 | 站点 `scrolling` / markdown `features/scrolling/` |
| 过时成员（deprecated）与迁移动作 | 站点 `compat-matrix` 的过时成员节 |
| 架构边界与兼容缺口 | 站点 `known-limitations` |
| 兼容状态（完全 / 部分 / 未支持） | 站点 `compat-matrix` |
| 字段、类型、签名、默认值 | `api.json` 驱动的参考页（`table-api` / `column-api` / `grid-options` / `public-api`） |
| 迁移步骤 | 站点 `migrate-from-antd` |
| “值不值得迁” | 站点 `when-to-migrate` |
| 能力清单与能力域入口 | 站点 `features` |

### 允许的重复

- **自包含交付物**：`migrate-from-antd` 里复制给外部 AI 的迁移提示词自带一份兼容边界摘要——它会被复制出站点单独使用，必须自包含。这类副本要注明“自包含”，并在正典页存在时指向正典。
- **首页摘要**：`HomePage` 的能力速览是站点门面，可以摘要正典内容，但不得引入正典没有的新结论。
- **表格里的一行结论**：参考 / 矩阵类表格可以用一句话复述结论，不展开理由。

### 页面尾部

每页最多一个「相关」块，且不重复左目录已有的条目。纯索引交由左目录与顶栏搜索承担，不逐页抄。

删除或合并页面时，旧 URL 必须在 `src/DocsPage.tsx` 的 `docAliases` 里保留映射（例如 `intro → quick-start`、`scroll-y → scrolling`）。
