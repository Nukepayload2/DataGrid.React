# #48938 Table virtual + Modal 跑版

## 现象
antd 5.11.5 把开启 `virtual` 的 Table 放进 Modal 中，外层渲染完成后**立即打开 Modal**，Table 的自定义横向滚动条**位置错乱/无法拖拽**（"跑版"）。根因是 Modal 弹出动画期间 Table 容器尺寸尚未稳定，虚拟滚动条测量到的容器宽度是中间态值。

## 复现 / 触发条件
- antd 5.11.5 + React 18.2 + Windows Chrome
- Table 启用 `virtual` + `scroll.x`，外层包 Modal
- Modal 一打开就立刻显示 Table（而非等动画结束）

## 期望 vs 实际
- 期望：Modal 出现后滚动条位置正确、可正常拖拽。
- 实际：滚动条浮在错误位置、拖拽行为异常。

## 根因 / 关键讨论
- 维护者 (@zombieJ 风格) 一句话定调："**看起来 scrollbar 也需要一个 resize 更新…**"
- 即：rc-virtual-list 的滚动条只测量一次容器宽度，没有监听容器尺寸变化（ResizeObserver/element resize）；Modal 动画期间宽度从 0 → 目标值，滚动条用旧测量值布局导致跑版。
- 无 linked PR，issue 至今未关闭。

## 对 data-grid 的启示
data-grid 的 `FloatingScrollBar`（以及任何依赖容器宽度的虚拟化计算）必须挂 `ResizeObserver` 持续监听 `.dg-wrapper` 尺寸变化，**绝不能只在 mount 时测量一次**。需覆盖回归场景：Modal/Drawer/Popover/Collapse 折叠面板/Tab 切换/分栏 SplitDemo——任何容器尺寸异步变化的父组件都可能触发同类跑版。VirtualizationContext + SplitDemo 限高 400 的场景已在记忆中记录，需把 ResizeObserver 作为虚拟化的硬依赖而非可选优化。
