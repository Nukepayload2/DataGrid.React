# #46640 Scrollbar Issue on Table elements on iPad Devices

## 现象
在 iPad 设备上（测试机型：iPad Pro 12.9 2020），使用 Safari 或 Chrome 浏览 antd Table 时，纵向滚动条表现"glitchy"（卡顿/闪烁），当表格同时存在水平滚动时问题更明显。一年后另一用户补充：V4 版本 table 上 iPad Safari 的右侧固定列（fixed right）**挡住了竖向滚动条**，看不到也无法拖动。

## 复现 / 触发条件
- 设备：iPad Pro 12.9 2020，Safari 与 Chrome。
- antd 4.24.3 / React 18.2 / macOS 宿主。
- 访问 https://ant.design/components/table#components-table-demo-grouping-columns。
- 表格上下滚动，尤其水平+垂直双向可滚时。

## 期望 vs 实际
- 期望：滚动条在 iPad 上与其他设备一致平滑滚动。
- 实际：滚动条卡顿；后续反馈为右固定列覆盖了竖滚动条位置，遮挡了用户操作。

## 根因 / 关键讨论
- 维护者 MadCcc 加 `🤔 Need Reproduce` 后又改加 `📱Mobile Device` 移除复现要求——即承认是 mobile-specific 已知差异。
- Contributor chenshuai2144 解释：v4 用 `position: sticky` 实现固定列；启用 `virtual` 属性可走虚拟滚动路径，`rc-virtual-list` 只负责水平滚动，固定列复用 sticky 样式。
- 一年后反馈者补充截图显示 iPad Safari 上 fixed right 列**遮住**滚动条，仍未解决。

## 对 data-grid 的启示
1. **iPad/Safari 滚动条覆盖检测**：iOS Safari 默认 overlay 滚动条不占布局空间，而 antd 预留了 scrollbar width。data-grid 若用 CSS Grid 共享 track（列定义对齐由 grid 而非像素补偿），可**结构性免疫**此类遮挡；但需在 iOS 真机做 overlay vs classic 滚动条 A/B 验证。
2. **`position: sticky` 在虚拟滚动下的兼容**：antd v4 用 sticky + virtual 复用固定列。data-grid 已有 `virtualization-toggle` 记忆，虚拟化模式下固定列若也用 sticky，需在 iPad 上专门验证触控滑动手感（没有 hover、惯性滚动差异）。
3. **触屏滚动惯性**：iOS momentum scroll 与虚拟化 RAF 易耦合漂移（见 `virtualization-virtuoso-aligned.md`）。data-grid 若用 JS RAF easing 做 smooth，需在 iPad 上禁用或回退为原生 instantaneous，避免与 Safari 惯性叠加出现"glitchy"观感。
4. **移动端独立测试矩阵**：本 issue 提示桌面 hover/scroll 行为不能替代移动端验证，应在 iOS Safari / iPad Safari 各跑一次 SplitDemo 双栏对比。
