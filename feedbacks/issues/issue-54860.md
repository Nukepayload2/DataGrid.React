# #54860 table组件使用colspan对固定列设置合并时单元格偏移错误

## 现象
当列 0、1 都是 `fixed: left` 固定列，并通过 `onCell` 返回 `colSpan` 合并单元格时（例如第 1 行里第 0 列 `colSpan: 0` 隐藏、第 1 列 `colSpan: 2` 向前合并），第一行固定列的 `left` 偏移会被错误地计算为 `width[0]`，导致固定列与表体出现错位/重叠。

## 复现 / 触发条件
- antd 5.27.2 + React 19.1.0，Chrome 139 / Win10。
- CodeSandbox: https://codesandbox.io/p/devbox/gu-ding-lie-antd-5-27-0-forked-sxp5xx
- 关键代码：
  ```ts
  // 第 0 列
  onCell: (_, index) => ({ colSpan: index === 1 ? 0 : 1 }),
  // 第 1 列
  onCell: (_, index) => ({ colSpan: index === 1 ? 2 : 1 }),
  ```

## 期望 vs 实际
- 期望：第一行固定列 left 偏移为 0。
- 实际：第一行固定列 left 偏移为 `width[0]`，被合并的单元格没有从 offset 累加中剔除。

## 根因 / 关键讨论
DosuBot 回复指出这是 antd Table 的架构级限制：内部固定列 `left` 偏移计算仍基于"所有前置列宽度累加"，并没有感知 `onCell` 返回的 colSpan 实际渲染结构，因此合并/被隐藏的单元格会污染偏移。常见规避：避免在固定列上使用 colSpan/rowSpan、关闭虚拟滚动、或显式指定 `tableLayout="auto"` 并手填列宽——都不能保证根治。仓库已挂 PR `react-component/table#1315`（fix: table onCell-method cause offset in width calculation）但尚未合并；2025-10-16 被打上 `Inactive`。

## 对 data-grid 的启示
CSS Grid 布局下固定列不再走绝对定位 + left 累加，但同样要在"固定列区域"和"合并单元格"共存时保证：
1. 计算 fixed 偏移时跳过 `colSpan: 0` 的隐藏单元格，按真实渲染结构累加；
2. 合并单元格不应突破 sticky 列边界（合并后的格子要么整体进入固定区，要么整体留在表体）；
3. 为这种"colSpan + fixed"组合准备回归用例（行 1 第 0 列隐藏、第 1 列 colSpan 2），避免重蹈 antd 的偏移污染路径。
