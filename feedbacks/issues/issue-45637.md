# #45637 虚拟滚动 Y 轴步长 deltaY 太大

## 现象
antd 虚拟 Table 在鼠标滚轮滚动时，单次 wheel 的 `deltaY` 被直接套用（~100px），轻轻一滚就会跨好几行，**用户感觉滚动跳跃、不流畅**，低性能设备上更明显——步长过大会触发频繁 DOM 增删，进一步放大卡顿感。

## 复现 / 触发条件
- 鼠标滚轮（非触摸板），尤其 Windows
- 列数 ~40 的大表格 + 虚拟滚动
- 低配电脑/虚拟机（2 核 4G）更容易感知

## 期望 vs 实际
- 期望：缩小 Y 轴 wheel 步长或暴露 API 让用户自定义，使滚动细腻、单位刻度更接近原生。
- 实际：rc-virtual-list `hooks/useFrameWheel.ts` 直接读 `event.deltaY`，无任何缩放/可配置项。

## 根因 / 关键讨论
- 作者定位到精确代码位置：`rc-virtual-list/hooks/useFrameWheel.ts` 的 `onWheel` 直接消费 `event.deltaY`。
- 作者 hack 验证：在 `node_modules` 里把 deltaY 除以 5，体验"明显细腻流畅"。
- 维护者 @Wxh16144 尝试后表示"没啥效果"，请求作者提供 patch 仓库复现。
- 作者补充：高配电脑难复现，需低配机或虚拟机 + 大量列才能感知差异（因为步长大 → DOM 频繁增删 → 低配机更卡）。
- 横向 X 轴步长同样过大。
- 27 条评论，长期未合并修复。

## 对 data-grid 的启示
与 #44972 同源问题。data-grid 设计虚拟滚动时：①优先让浏览器原生滚动容器处理 wheel（无需自写步长逻辑）；②若必须自实现 wheel 监听，应提供 `wheelStepScale`/`scrollFactor` 配置项；③测试矩阵必须覆盖"低配机+大列数"场景，否则体感问题在高配开发机上不可见——这是 antd 长期忽视的根因。
