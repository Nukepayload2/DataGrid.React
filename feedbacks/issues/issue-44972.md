# #44972 虚拟列表滚动条滚动效果和原生不一致

## 现象
开启 antd Table 虚拟滚动后，**滚轮手感明显比原生更快**——同样的滚轮刻度，虚拟表滚动距离更大，缺乏"阻尼感"，用户主观体验与原生滚动条差异显著。即便只有十几条数据（实际全部渲染出来），现象依然存在，证明与数据量无关，而是滚轮事件到 scrollTop 的换算系数偏大。

## 复现 / 触发条件
- antd Table 由非虚拟切换为 `virtual`
- 用鼠标滚轮滚动（尤其 Windows 高分辨率滚轮鼠标）
- 即使数据量小（十几行）也复现，排除性能卡顿

## 期望 vs 实际
- 期望：滚轮阻尼、单位刻度位移量与浏览器原生滚动条一致。
- 实际：滚动明显偏快，用户难以精确定位到某一行。

## 根因 / 关键讨论
- 维护者最初怀疑是"卡顿"，作者反驳：数据量小、全部行已渲染、纯粹是滚轮速度系数问题。
- 评论中另一用户补充：开启 virtual 后 `components` 自定义元素失效；列数 50+ 拖拽卡顿。
- 根因方向：rc-virtual-list 监听 wheel 事件后自行累加 scrollTop，未对照浏览器默认的 `deltaY * line-height * 系数` 换算规则（不同操作系统/设备像素比下系数不同）。
- Issue 已关闭（未明确修复，可能是 wontfix 或后续版本隐性改善）。

## 对 data-grid 的启示
data-grid 虚拟滚动应**优先复用浏览器原生滚动容器**（真实滚动条 + 内部 Filler 占位），让滚轮→位移的换算交给浏览器，避免自行实现 wheel 监听带来的阻尼失真。如必须自实现（横向 FloatingScrollBar），wheel 系数需对照 Chrome 默认行为校准（Windows 通常 100px/刻度，macOS 视动量滚动平滑）。这是 react-virtuoso 选择"真滚动容器"而非"transform 偏移"的关键原因。
