# #37995 Table shouldCellUpdate

## 现象
rc-table/antd Table 提供 `column.shouldCellUpdate`，期望「返回 true 时该单元格的 `render` 应当重新执行」。OP 用 setState 改一个字段，触发按钮点击后 `shouldCellUpdate` 确实返回 true，但单元格 render 没有重新执行，UI 不变。

## 复现 / 触发条件
- antd 4.23.5 + React 17（Codesandbox 复现链接）。
- columns 用 `useMemo` 缓存；点击按钮只改 record 的某个字段（不替换 record 引用）。
- `shouldCellUpdate(record) { ... return true }` —— render 不触发。

## 期望 vs 实际
- **期望**：`shouldCellUpdate` 返回 true 等价于 React 的 `shouldComponentUpdate`，强制本单元格重渲染。
- **实际**：源码里 rc-table 的 Cell（`Cell/index.tsx#L184`）即便 `shouldCellUpdate` 返回 true，也只是「允许」更新——真正决定 render 是否执行的还是 React 的 props 比较；如果 columns 缓存、record 引用未变，依然跳过。

## 根因 / 关键讨论
- MadCcc（antd member）给了 workaround：在 Codesandbox 里 `setState` 时传一份**不同的 data**（替换 record 引用）即可触发 render。
- OP 进一步自答：`shouldCellUpdate` 返回 true 并不保证 render 重跑；可靠做法是**创建新的 columns 或新的 record（浅拷贝 `[...record]`）**。仅改字段值不替换 record，UI 不会变。
- 第三位用户补充："I fixed this issue by replace the row object with a new by creating a full copy object from row"（代码示例）。
- 维护者未承诺修改语义；issue 被打上 `Inactive`。

## 对 data-grid 的启示
1. **API 设计警示**：`shouldCellUpdate` 这种命名容易让用户误以为它是 React 层面的 update gate。data-grid 如果提供同名/同概念 API，必须在文档里写清楚：它只是「允许」重渲染，最终是否 render 仍由 React 调和决定。
2. **更直观的替代方案**：data-grid 可以考虑 `getCellValue`/`reactive` 之类的「响应式单元格」API，让用户显式声明依赖；或借鉴 Vue/tanstack-table 的 `render` 是函数式 render（依赖全靠参数）避免歧义。
3. **回归用例**：缓存的 columns + 只改字段值不换引用 + `shouldCellUpdate => true` 三种组合，都要测一遍，确保文档语义与实际行为一致；并补一条「替换 record 引用」的正解示例到 FAQ。
4. **虚拟化场景下尤其关键**：data-grid 虚拟滚动会按行 memoize，shouldCellUpdate 这类 hook 是行级 re-render 的闸门；要把它和 React.memo 的比较函数清晰分工，避免「返回 true 却不更新」的悖论。
