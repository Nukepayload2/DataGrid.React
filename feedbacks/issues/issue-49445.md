# #49445 希望恢复表格设置 body 固定高度的 API

## 现象
antd Table 没有任何 API 能让「表体固定一个高度」（不是 `max-height`）。当数据条数变化时，分页条会随内容上下跳动，业务方很反感。

OP 的诉求很明确：要一个**不论数据多少都保持固定高度**的 bodyHeight/style.body API，可以是数字或百分比。

## 复现 / 触发条件
- 用 antd `<Table scroll={{ y: 600 }} />`。
- 数据只有 1–2 条时，表体实际高度远小于 600px，分页条紧贴数据上移。
- `scroll.y` 编译出来的 CSS 是 `max-height: 600px`，并不是 `height: 600px`。

## 期望 vs 实际
- **期望**：提供 `bodyHeight` 或 `styles.body` 一类的 API，**强制表体为固定高度**；分页条位置不动。
- **实际**：v5/v6 长期没有官方方案。`scroll={{ y: 600 }}` 仅作上限；`styles.section.minHeight` 会把表头也算进去，超过 `scroll.y` 时下面会留一片空白；`styles.body.wrapper.minHeight` 又会错误地作用到 `tbody`（`ant-table-tbody`）而不是滚动容器 `div.ant-table-body`，导致内部撑不开、被外层限死。

## 根因 / 关键讨论
- 维护者 afc163 反复追问 "最好先给个问题重现" 与 "`scroll={{ y: 600 }}` 这个能满足需求么？"，OP 明确解释该 API 是 `max-height` 语义，不是固定值。
- ybf970928 给出 workaround：`styles.section.minHeight` 不要超过 `scroll.y`，可以"撑开页面让分页下去"，但滚动条会撑不开、视觉不美观。
- OP 的自研方案：手动算 `scrollY`，再 `style={{ '--body-height': scrollY }}`，CSS 里 `.ant-table-body { height: var(--body-height); }` 覆盖 —— 等于回到 v4 时代手搓样式。
- 后续评论中有人补 "Footer 不要放到滚动区域里面去，滚动应仅限数据行"（与 summary/pagination 的层级讨论相关）。
- 该 issue 至今未关，反映 antd v6 `styles.section` / `styles.body.wrapper` 的层级语义仍不满足"固定表体高度"用例。

## 对 data-grid 的启示
1. **一等公民 API**：data-grid 应直接提供 `bodyHeight`（数字 / 字符串 / 百分比）作为 **固定高度**语义，并明确和 `scroll.y`（最大高度）的分工 —— 解决本 issue 34 条评论的核心痛点。
2. **CSS 变量天然契合**：本仓 CSS-Grid 重做架构里 `--dg-body-height` 可以直接作用到正确的滚动层（`.dg-data-area`），不会像 antd 那样错误落到 `tbody`。把"作用层"语义在文档里画图说清楚。
3. **分页位置**：分页条要在固定高度外（sibling），不要做进滚动容器（参考评论"Footer 不要放到滚动区域里面去"）。`wrapper` 高度 = `header + bodyHeight + pagination + summary`。
4. **回归用例**：1 条数据 + bodyHeight=400，断言表体高度恒为 400、分页条位置不变；并补 `bodyHeight < scroll.y` / `bodyHeight > scroll.y` 两组语义边界。
5. **文档对照**：可写一篇「antd 用户迁移指南」专章，说明 data-grid 的 `bodyHeight` 等价于本 issue 期望但 antd 至今没给的 API，作为差异化卖点。
