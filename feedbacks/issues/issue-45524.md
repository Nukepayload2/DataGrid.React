# #45524 虚拟滚动表头频发性位置错乱

## 现象
开启 Table 虚拟滚动后，快速左右拖动横向滚动条时，**表头会向左偏移**，与表体列错位；列越多、拖得越快越容易复现。偶发伴随鼠标移动监听未解绑（鼠标离开 Table 后滚动条仍在被拖）。

## 复现 / 触发条件
- antd 5.10.2（官方 demo 即可复现）
- Windows + Chrome 103（macOS / Edge 难复现）
- 启用 `virtual` + `scroll.x` + `scroll.y`（垂直滚动条必须出现）
- 将横向滚动条拉到右侧，然后快速向左拖拽，让鼠标脱离 Table 区域
- 列数多时更易触发

## 期望 vs 实际
- 期望：表头始终与表体列对齐，鼠标离开后拖拽立即终止。
- 实际：表头位置错乱向左偏移；mouse move 监听器未释放。

## 根因 / 关键讨论
- 维护者（@zombieJ、@MadCcc）起初无法复现，要求在线 repro；作者补充 gitee 仓库 + GIF 后才确认。
- 关键线索：拖拽事件监听挂在 `window`/`document` 上但 mouseup 未正确解绑，导致位置状态未同步到表头同步逻辑；不同浏览器拖拽事件时序差异导致 Windows Chrome 易复现。

## 对 data-grid 的启示
- 横向滚动条拖拽监听必须挂在 `window`，并在 `mouseup`/`pointerup` + `visibilitychange`/`blur` 多路径解绑，避免鼠标脱离后监听器悬挂。
- 表头同步走 CSS Grid `grid-template-columns` 共享同一列定义（data-grid 已这么做），从根本上杜绝"表头独立维护 scrollLeft 导致漂移"的antd 式 bug。
- 必测：快速/越界拖拽、鼠标离开窗口、切换标签页再回来、Windows Chrome 优先回归。
