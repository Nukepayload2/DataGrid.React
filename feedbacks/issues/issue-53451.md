# #53451 拖拽排序 + ellipsis + 自定义 Tooltip 触发首行拖拽

## 现象
Table 同时启用：
- 行拖拽排序（row drag handle）；
- `column.ellipsis = true`；
- `column.render` 返回的内容用 Tooltip 包裹，Tooltip 内容里有可选中文本/链接。

用户把鼠标移到 ellipsis 单元格的 Tooltip 浮层上，尝试用鼠标拖动选中文本时，事件冒泡到表体第一行，触发了第一行的拖拽（行被错误地拖动）。

## 复现 / 触发条件
1. 列：`ellipsis: true` + `render` 返回 `<Tooltip title={...}>...</Tooltip>`；
2. 启用 dnd 拖拽手柄；
3. 悬停某行 ellipsis 单元 → Tooltip 弹出；
4. 用鼠标在 Tooltip 内容上拖选文本 → 表格首行被一起拖动。

## 期望 vs 实际
- **期望**：在 Tooltip 内容上选中文本不应触发表格行拖拽。
- **实际**：mousedown 事件冒泡到行容器，被 dnd 监听器当作 drag start。

## 根因 / 关键讨论
- 维护者（看起来是机器人 petercat + 真人回复）："冒泡问题，但 Tooltip 不适合直接加 preventDefault。可参考 antd-mobile 搞个 `preventDefault` 属性让用户配置。"
- 问题本质：Tooltip 浮层默认 render 到 body，事件链路穿过表体；dnd 监听 mousedown 在 row 层，没有"事件来自浮层"的过滤逻辑。
- ellipsis 是触发条件——非 ellipsis 单元不挂 Tooltip，就没问题。

## 关联图片
无（仅复现链接）。

## 对 data-grid 的启示
1. data-grid 设计行拖拽时，应在 row 的 mousedown 监听里判断 `event.target` 是否在 drag handle 之内（手柄显式优先），而不是"任意 mousedown 都可以拖"。
2. 浮层（Tooltip、Dropdown、Popover）若挂载在 body，使用 portal + `event.stopPropagation()` 在浮层根节点阻止冒泡；或 dnd 监听 `pointerdown` 时检查 `composedPath()` 是否经过 `[data-drag-handle]`。
3. 提供 `rowDragTrigger: 'handle' | 'cell' | 'row'` 显式开关，避免整行可拖的隐式行为。
4. ellipsis + Tooltip 是常见组合，data-grid 把 ellipsis Tooltip 作为内置功能（自动接管）而非让用户拼装，能从源头避免事件冲突。
