# #49437 [feat] 固定表格分页选择器

## 现象
表格分页器在 `position: "topXXX"` 配合 `sticky` 设置时不会固定在顶部，而是随表体内容一起滚动。用户在大数据量场景下浏览到中部想换页时，必须滚回顶部或底部才能找到分页栏。

## 复现 / 触发条件
使用 `<Table sticky />` 加 `pagination={{ position: "topLeft" }}`（或 `topRight`），向下滚动表体，分页器随之移出视口。

## 期望 vs 实际
- **期望**：分页器像表头一样吸附在表格顶/底边。
- **实际**：分页器是表体外独立元素，sticky 只作用于表头，分页栏被滚走。

## 根因 / 关键讨论
提议者提出 API `sticky = "title" | "pagination" | "both"`，把分页栏纳入 sticky 容器。维护者（afc-163）认为"分页滚动设计上看着会有点怪，主要是遮挡时的样式"，先打 feature request 标签待定。有多名 +1 用户补充：UI 设计稿常要求分页吸底，且分页空白区需要扩展定制；并对照已有的 `Table.Summary fixed={'top'|'bottom'}`，希望分页也获得同等能力。

## 关联图片
无。

## 对 data-grid 的启示
1. data-grid 的 CSS Grid 布局天然适合把分页栏做成 grid 区域（`grid-template-rows: header pagination body` 或独立 sticky 行），避免 antd 现有实现中分页与表体分离的局限。
2. 设计时把 sticky 拆为 `title` / `pagination` / `both` 三档，从 API 一开始就支持，避免后续改造。
3. 注意吸顶/吸底时下方边框的视觉遮挡——可考虑边框虚化或阴影分层。
4. `Table.Summary fixed` 已是社区习惯，data-grid 应保证 summary 和 pagination 都能各自 sticky。
