# #56334 提供组件级别的方式关闭 Popover 的动画

## 现象
antd 6.1.0 下，Popover 的开关动画（leave 动画）无法在组件级别关闭。`motion={{ motionName: 'xxx' }}` 只是替换动画 className，并不会真正禁用 —— Popover 关闭时仍有一个明显的停顿/淡出延迟。v5 及更早版本的 `transitionName="xxx"` 行为相同。

## 复现 / 触发条件
- `<Popover motion={{ motionName: 'xxx' }}>...</Popover>`（或 v5 `transitionName`）。
- 打开 trigger A，再点开 trigger B —— 关闭 A 时的 leave 动画带来肉眼可见的停顿。
- 若设 `motionName=""` 或 `false`，底层仍会生成默认 className 触发 rc-motion 动画逻辑，禁不掉。

## 期望 vs 实际
- **期望**：组件级别能彻底关掉动画（与全局 `ConfigProvider.theme.token.motion: false` 同效果），且不影响别的 antd 组件。
- **实际**：唯一官方关闭动画的方式是全局 `ConfigProvider` 把 `theme.token.motion: false` —— 一关关全部。

## 根因 / 关键讨论
- dosubot 复述源码：Popover 内部始终会传一个 `motionName`，导致关闭时仍有动画延迟；自定义 `motionName` + CSS `animation: none !important` 的 workaround 可能有副作用（动画事件未触发 → DOM 清理异常）。
- OP 进一步澄清性能场景：Popover 在表格内部循环 + 性能敏感处使用，外面再包一层 `ConfigProvider` 会带来「不必要的性能损耗」，且作用域太大，会把整个 Table 下所有 antd 组件的动画都关掉。
- 维护者 MadCcc 回应："目前可以通过直接包一个 ConfigProvider 去实现，我们不太会在组件上直接透出 motion 属性" —— 即**官方立场**：只保留全局开关，不打算下沉到组件级别。
- issue 仍 Open，但维护者明显倾向于不提供组件级 API。

## 对 data-grid 的启示
1. **反方向设计**：data-grid 内部用到的浮层（Filter 下拉、编辑器气泡、Tooltip）应**默认就是无动画**或**动画可关**——尤其浮层嵌在虚拟滚动表体里时，`rc-motion` 这种 leave 动画会拖累交互。
2. **API 优先级**：把 `motion: false` 下沉到**单元格级别**（`column.motion`、`cell.popoverMotion`），让用户能精准关掉某列编辑器气泡的动画 —— 正面解决本 issue 的痛点，作为差异化卖点。
3. **性能考量**：本 issue OP 提到的「表格内部循环 + 性能敏感」与 data-grid 虚拟滚动场景一致。浮层动画的 RAF/transition 在大数据量下会放大开销；默认行为应避免。
4. **回归用例**：在 1k 行数据里循环触发某列的 Popover 编辑器，开/关 motion 对比帧率；保证「关动画」真正等价于「直接卸载 DOM」，而不是「只是 CSS opacity 立刻为 0 但仍跑 transition」。
5. 与 antd 全局 `theme.token.motion: false` 区分清楚：data-grid 的 motion 开关是**组件级**，不会波及应用内其他 antd 组件。
