# #56356 表格可伸缩列不跟手、位置偏移、无法退出拖拽

## 现象
用户在 antd 6.1.1 / React 19 / Windows 11 + Edge 143 上反复拖拽官网"可伸缩列"demo 第一列宽度时遇到三个问题：
1. 性能卡顿（拖拽不跟手）。
2. 鼠标位置与拖拽手柄失去同步。
3. 鼠标松开后仍处于拖拽中状态，需要再点击一次才能退出。

作者补充背景：他在实现"拖拽只改变两列宽度，不改 scroll.x"的功能时发现给所有列设 width 后拖拽异常卡顿。官网 demo 因为最后一列未设 width 所以卡顿较轻，但仍存在不跟手现象。明确**拒绝 `tableLayout=fixed` 临时方案**（带来布局问题），也**拒绝 `scroll.x='max-content'`**（破坏自动换行 + 强制横滚动条）。作者把 AG Grid（https://www.ag-grid.com/example/）作为预期行为标杆。

## 复现 / 触发条件
- 打开 https://ant-design.antgroup.com/components/table-cn#table-demo-resizable-column。
- 反复拖拽第一列宽度。
- 附件：ant-design-56356-复现视频.zip。

## 期望 vs 实际
- 期望：性能流畅；鼠标与拖拽手柄同步；松开鼠标必退出拖拽（参考 AG Grid）。
- 实际：三端全失败——卡顿、位置漂移、状态卡死。

## 根因 / 关键讨论
dosubot 解释：当前实现依赖 `react-resizable`（https://github.com/react-grid-layout/react-resizable），**该库已多年不维护**，无拖拽生命周期管理或 cleanup，mouseup/pointerup 丢失时拖拽状态卡死。每帧 `setColumns` 触发整表重渲染是性能瓶颈；React 19 下更明显。

## 对 data-grid 的启示（★ 本批最重要）
1. **官方已放弃Resizable 列方向**：antd 官方明确**下掉了可伸缩列 demo**，外部依赖（react-resizable）不维护。这是 data-grid 差异化亮点——如果能内置高质量可伸缩列，将直接吃下这部分用户需求。
2. **拖拽生命周期必须有 cleanup**：mouseup/pointerup/touchend/unmount 全要监听，cursor 强制 reset，避免"松开后仍卡在拖拽"状态。这是 data-grid 实现时必须正确处理的状态机。
3. **拖拽性能：用 ref + RAF，避免每帧 setState**：拖拽过程中宽度暂存到 ref/RAF 队列，结束后再 commit 到 state；不要每帧 setColumns。这正契合 data-grid CSS Grid 列宽架构（grid-template-columns 字符串单点修改即可，无需重渲染整个表）。
4. **对 debounced handler 慎用**：dosubot 建议 debounce，但这会加延迟；更好的方案是 CSS Grid 下"只改 grid-template-columns 一条字符串"，浏览器原生处理列宽，性能天然优于 React 重渲染。
5. **自动换行 + 不出现横滚动条 + 列定宽 三个约束的冲突**：用户明确要求三者共存，antd 无解。data-grid 的 `column-width-scrollbar-policy.md`（`auto` → `minmax(min-content, 1fr)`）正好是解药：列定宽可拖拽，剩余列走 1fr 弹性，且不会出现裸 max-content 的横滚动条。
6. **AG Grid 是用户标杆**：data-grid 应对比 AG Grid 的拖拽手感（跟手度、惯性、视觉反馈）做 A/B，作为可伸缩列的验收标准。
