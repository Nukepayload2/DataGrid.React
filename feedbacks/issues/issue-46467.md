# #46467 ref.scrollTo 外层有滚动条时连外层一起滚

## 现象
Table 实例方法 `ref.current.scrollTo({ index: N })` 在表格嵌入一个有滚动条的父容器时，会同时滚动外层容器——调用一次 scrollTo，外层页面也被顶到目标行位置，用户视觉上表格外层闪动。

## 复现 / 触发条件
1. `<div className="container">` 自身 `overflow: auto` 或页面有滚动条；
2. 内部 `<Table scroll={{ x: 1500, y: 300 }} ref={tableRef} />`；
3. 点击按钮调用 `tableRef.current.scrollTo({ index: 2 })`；
4. 外层容器（或页面）一并滚动。

## 期望 vs 实际
- **期望**：scrollTo 只影响表体内部，外层视口保持不变。
- **实际**：外层和表体同步滚动。

## 根因 / 关键讨论
- 维护者（team）确认是 bug，根因在 `react-component/table` 的 `Table.tsx` 第 331 行附近——内部用了原生 `Element.scrollIntoView()`，而 scrollIntoView 会沿 DOM 树逐层滚动所有可滚动祖先，无法限定到表体。
- 临时解决：开启 `virtual` 模式（虚拟列表内部走另一条路径，不调 scrollIntoView）。
- 有用户追问：scrollTo 是否支持 X 轴？目前只支持 Y。

## 关联图片
无（仅代码复现）。

## 对 data-grid 的启示
1. **核心避坑**：data-grid 的 `scrollTo({ index, key })` 实现必须**直接设置表体容器的 scrollTop**，绝不要使用 `scrollIntoView()`——scrollIntoView 的"链式滚动"行为是浏览器规范，无法关闭。
2. 虚拟化和非虚拟化路径要统一走"内部 scrollTop 赋值"，避免像 antd 一样两条路径行为分裂。
3. 提供 `scrollTo({ index?, key?, left?, top?, behavior? })` 一开始就支持 X 轴与 Y 轴，避免后续补丁。
4. 测试矩阵：在 overflow:auto 的父容器、页面有滚动条、嵌套多个滚动容器三种场景下断言只有表体变化。
5. 关联 data-grid 的 offsetTree/AATree 虚拟化已对齐 virtuoso，可天然避开此坑。
