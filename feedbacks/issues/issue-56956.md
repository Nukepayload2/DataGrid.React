# #56956 统一 virtual / 非 virtual Table 的滚动条样式

## 现象
三处滚动条样式不一致：
1. **virtual vs 非 virtual**：virtual 用 rc-virtual-list 自定义滚动条，非 virtual 用浏览器原生滚动条，两者外观/位置不对齐。
2. **virtual 空数据**：稳定复现，虚拟表格在 `dataSource` 为空时回退为原生滚动条，对动态数据表格来说视觉跳变。
3. **virtual 只有横向滚动条**：不稳定复现，纵向未溢出但横向溢出时，横向滚动条会"变回"原生样式。

## 复现 / 触发条件
- antd 5.x Table
- virtual=true，切换 dataSource 空/非空，或调列宽让只有横向滚动

## 期望 vs 实际
- 期望：virtual/非 virtual、空/非空、横/纵向组合下滚动条都统一为自定义样式。
- 实际：当前三种组合下滚动条形态不一致。

## 根因 / 关键讨论
维护者 afc163 认为是合理改进建议，明确根因：「虚拟滚动表格外层容器用 `overflow: auto`，非虚拟滚动则不同，导致滚动条位置不一致。」本质是「rc-virtual-list 的自定义 scrollbar」与「外层 div 原生 overflow」两套机制并存，在不同代码路径下各自接管，缺统一的 scrollbar 包装层。

## 对 data-grid 的启示
CSS Grid 重做 Table 时，横向 + 纵向滚动条要由同一个"虚拟滚动容器"统一接管（建议横向也用 FloatingScrollBar 自绘，不要让原生条出现在任何路径），并且 empty 数据分支、单轴溢出分支都要走同一个渲染路径，避免 antd 这种"按代码路径不同出现不同滚动条"的体验割裂。
