# #48715 table 组件嵌套子表格，设置 scroll.y 之后展示问题

## 现象
父表格设置 `scroll={{ x: 'max-content' }}`，同时子表格（嵌套展开行内）设置 `scroll={{ y: 300 }}`，子表格渲染时宽度异常膨胀到 `1e06px`（100 万像素），破坏整个页面布局。

## 复现 / 触发条件
- antd 5.16.4 / React 18 / macOS 14.1.2 / Chrome 123。
- 父表格 `scroll={{ x: 'max-content' }}`。
- 展开行中嵌套子表格，子表格 `scroll={{ y: 300 }}`。
- CodePen: https://codepen.io/TinyD-the-bashful/pen/gOyJpvR?editors=0010。

## 期望 vs 实际
- 期望：子表格宽度正常或可显式设置宽度后正常。
- 实际：子表格出现 `1e06px` 超宽，无法约束。

## 根因 / 关键讨论
官方维护者 afc163（Sep 3, 2025）将本 issue 关联到 #54268（Table 设置 `scroll={{ x: 'max-content' }}` 后内部 Description 组件宽度异常大），判定为同一根因——`scroll.x: 'max-content'` 在嵌套布局中会让内部组件/子表格的可测量宽度发散到天文数字，是 antd 在 `max-content` + 嵌套场景下的已知缺陷。本 issue 暂未修复，标记 Inactive/unconfirmed。

## 关联图片
无（issue 未附图）。

## 对 data-grid 的启示
1. **`scroll.x: 'max-content'` 陷阱**：data-grid 的列宽规约（`column-width-scrollbar-policy.md`）已明确 `auto` 用 `minmax(min-content, 1fr)`，而不是裸 `max-content`。本 issue 印证了裸 `max-content` 在嵌套结构中**会发散到 1e6px**，是必须规避的反模式。
2. **嵌套子表格的宽度隔离**：父表格用 grid track 分配宽度，子表格若嵌套于展开行内，需保证子表格拥有**独立宽度上下文**（不能继承父 `max-content` 的无穷大），data-grid 应让展开行 container 显式 `width: 100%` 或 `contain: layout`，避免父子相互触发 max-content 递归放大。
3. **展开行内嵌套 Table 测试用例**：data-grid 应增加 demo：父表格 `scroll.x` auto + 展开行内嵌套 data-grid 子表格带 `scroll.y`，验证宽度不爆栈。
4. **数值越界保护**：计算列宽时若出现 `1e6px` 量级结果应触发断言/兜底（如最大视口宽度的 N 倍截断），便于早发现类似 bug。
