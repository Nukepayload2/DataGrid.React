# #53918 expand 图标放在 select 图标前面 + children 自带渲染

## 现象
antd 5.22.6 / React 18 / macOS / Chrome。用户希望：
1. **展开图标排在选择框（多选框）前面**（即顺序：展开 → 选择 → 数据列）；
2. **数据里的 `children` 字段自动渲染为子表格**，而不用手写 `expandedRowRender`。

实测 `Table.EXPAND_COLUMN` / `Table.SELECTION_COLUMN` 都无法调整展开与选择的相对顺序（选择框始终在最左），`expandedRowRender` 也"不支持渲染 children 自动渲染表"，必须自己实现。

## 复现 / 触发条件
- 在 `rowSelection` + `expandable` 同时开启时，展开图标固定在选择框之后。
- `expandable.expandIconColumnIndex` 只能控制展开图标在"数据列之间"的位置，不能插到 selection column 之前。

## 期望 vs 实际
- 期望：自由配置 `[expand, selection, ...data]` 这种列顺序，且 `children` 字段自动展开成嵌套表。
- 实际：选择框永远在最左，展开图标只能在数据列之间移动；`childrenColumnName=children` 默认能自动渲染嵌套子表，但与 expand 图标位置无法同时满足。

## 根因 / 关键讨论
- Dosu 指出：`expandable.expandIconColumnIndex` 只能控制"数据列之间"的索引，selection column 是硬编码在最左侧的。
- OP 的 workaround：隐藏 expand 图标 → 在 select 图标前加 `::before` 伪类 → 用伪类触发展开。简单但 hack。
- OP 进一步提到："如果第一列是 DndTable 的可拖拽手柄，那么加号会在拖拽手柄列前面，很违和，应该是拖拽手柄列在前面才合理。"
- 维护者（design 团队）回复："设计是加号放在第一个字段前，暂时没有计划调整"——明确 won't fix，加号位置被设计锁死。

## 对 data-grid 的启示
1. CSS Grid 下，"展开列 / 选择列 / 拖拽手柄列 / 数据列"应当是同一抽象——都是"前置特殊列"，顺序应当完全可配置（`leadingColumns: ['expand', 'drag', 'selection', ...]` 或类似 API），不要硬编码 selection 必须最左。
2. 这是与 antd 拉开差异的机会：data-grid 可以原生支持 `expand` 在 `selection` 之前的顺序，且对 DnD 手柄、序号列等"工具列"做一致抽象。
3. `children` 字段自动嵌套渲染（tree data）应与 `expandedRowRender` 解耦：有 children → 自动树形；有 expandedRowRender → 自定义内容；二者可以共存（外层自动树形、内层自定义），避免用户被迫二选一。
4. 注意设计权衡：加号位置"约定俗成在最左"是有用户习惯的，data-grid 默认可保持 antd 行为，但要让"自定义顺序"成为一等公民，不能像 antd 这样直接拒绝。
