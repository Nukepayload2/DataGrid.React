# #36066 table 的子表格实现吸顶功能

## 现象
当外层 Table 通过 `expandable.expandedRowRender` 嵌套了内层 Table，且内层数据很长时，内层 Table 的表头会随滚动消失，用户失去列含义参考。同样问题也适用于任意"普通数据行"——希望任意行能"吸顶"（多行时支持渐次吸顶）。目前 antd Table 的 `sticky` 只对外层表头生效，嵌套表格/普通行的 sticky 没有官方方案。

## 复现 / 触发条件
- 在 `expandable.expandedRowRender` 中返回一个 `<Table sticky />`，且内层 Table 数据较多需要滚动时，向下滚动后内层表头不固定。
- 或者：外层 Table 表体超长，希望某行（例如分组的"小计"行）在视口顶部贴住。

## 期望 vs 实际
- 期望：
  - 内层 Table 的 header 在其父容器（展开行）内吸顶；
  - 或者外层 Table 的任意数据行可设为"sticky"，多行时依次渐次吸顶。
- 实际：antd 内层 Table 的 sticky 不生效；普通行也没有 sticky API。

## 根因 / 关键讨论
提议的 API：
```tsx
<Table stickyRow={(row) => boolean} expandable={{ expandedRowRender }} />
```
即对每行返回一个布尔，决定该行 `<tr>` 是否在视口顶部贴住。issue 提出后无维护者响应，2025 后进入 `Inactive`。

## 对 data-grid 的启示
1. CSS Grid 下做 sticky 比 `<table>` 自然得多：用 `position: sticky; top: var(--row-sticky-offset)` + `grid-row` 即可让任意行贴顶；可考虑提供 `rowSticky: (record, index) => boolean | number` API，返回偏移量让多行渐次叠放。
2. 嵌套 Table（展开行内的子表）的 sticky 表头要明确"参考系"——以展开行容器的顶为基准，而不是以视口顶为基准；data-grid 应让子表读取父展开行的高度作为 sticky `top`。
3. 虚拟滚动开启时，sticky 行需要从虚拟化排除（始终渲染），否则滚动重计算会丢帧；应在 gridOptions 里增加 `stickyRowIndices` 选项，引擎跳过这些索引。
4. 多级 sticky（分组小计 + 表头）要做堆叠顺序：表头 > 分组小计 > 普通行，offset 累加清晰可见。
