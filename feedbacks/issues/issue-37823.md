# #37823 删除当前页所有数据后页码变化未触发 onChange

## 现象
表格分页到最后一页（或任意页），删除当前页所有数据后，Pagination 内部把 current 修正到上一页，但这次页码变化没有触发 `onChange`，使用方无法收到通知去重新拉数据。

## 复现 / 触发条件
1. 受控分页 `pagination={{ current, onChange }}` + 远程数据；
2. 翻到最后一页；
3. 删除该页全部行，使本页数据为空；
4. Pagination 静默把 current 减 1，不调用 onChange。

## 期望 vs 实际
- **期望**：当 total 减小导致 current 自动调整时，仍触发 `onChange(newPage, pageSize)`，使用方能联动远程请求。
- **实际**：页码 UI 变了，回调缺失，应用显示空表。

## 根因 / 关键讨论
- 报告者指出：不止最后一页，第一页、中间页删除后页数变化同样不触发。
- 维护者（afc-163）回复："之前修复过，但是触发了 #33487 所以回滚了（changelog 4.18.2），新 PR 在 #33509"——即修复与回归反复拉扯，未能稳定落地。
- 问题本质：antd Pagination 内部对 "out-of-range current 自动纠正" 的逻辑没有把纠正结果同步回外部受控值，造成受控/非受控语义割裂。

## 关联图片
无（仅复现链接 CodeSandbox）。

## 对 data-grid 的启示
1. data-grid 设计分页时，必须把"内部修正 current"视为一次合法的 onChange，对外广播，避免 antd 受控/非受控割裂陷阱。
2. 测试矩阵要专门覆盖：删除整页、批量删除跨页、过滤导致 total 突然缩小的场景，断言 onChange 触发次数与新页码。
3. 参考 antd #33487 回归教训：修正逻辑要兼容"用户已受控设置 current"的情况，避免抢跑或循环触发。
4. 把 pagination 状态机集中化（单一真理源），不分散在表体/Pagination 组件内。
