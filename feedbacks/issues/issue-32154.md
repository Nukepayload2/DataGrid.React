# #32154 filteredValue 控制 filters 时 hide column 出错

## 现象
表格列使用受控筛选（`filteredValue` + `onFilter`），用户操作"隐藏该筛选列"时，受控列的筛选结果会丢失（数据恢复成未筛选状态）；而同样的操作对非受控筛选列（仅 `onFilter`）则行为正确——筛选结果保留。

## 复现 / 触发条件
1. 列：姓名 / 性别 / 年龄，三行数据；
2. 性别列设置 `filteredValue` 受控；
3. 在性别列筛选选择"女"，表中只剩"小花，女，18"；
4. 通过按钮 `columns[i].hidden = true`（或动态移除该列）隐藏性别列；
5. **实际**：数据变成"小明 / 刚子 / 小花"——筛选结果丢失；
6. **期望**：与非受控列一样，仍只显示"小花"。

## 期望 vs 实际
- **期望**：列隐藏只影响渲染，不应清除受控筛选状态，结果集保持一致。
- **实际**：antd Table 在 hide column 路径上把 `filteredValue` 一并丢弃，重新跑 filter pipeline 时拿不到原值。

## 根因 / 关键讨论
- 报告者用了官网示例改造的复现 demo，详细列出 A/B 对比表。
- zombieJ 一开始要更详细的重现步骤，作者补充后未见修复跟进。
- 根因：antd Table 内部 `getFilterProps`/`transformFilterColumns` 在列隐藏时未保留 filteredValue 引用，filter 状态被丢回 undefined。

## 关联图片
无（仅 CodeSandbox 复现链接）。

## 对 data-grid 的启示
1. data-grid 把"列隐藏"与"列的 filter 状态"显式解耦：hideColumn 不应触碰 filteredValue/filterState。
2. 列状态机要单一真理源（visibility / filter / sorter / width 各自独立字段），避免一个动作顺带清掉别的状态。
3. 单元测试覆盖：受控 filter + 动态列隐藏 / 列顺序调整 / 列替换三种场景，断言数据集稳定不变。
4. 这是 antd 长期未修的语义漏洞，data-grid 可作为差异化正确性卖点。
