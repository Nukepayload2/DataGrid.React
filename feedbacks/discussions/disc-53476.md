# disc #53476 table 组件平铺展示树形多选结构

## 现象
OP 想要一种「树形多选平铺」展示效果：父节点占一行，子节点作为**合并单元格**在右侧横向平铺展开，每个子节点都带 Checkbox（独立多选）。常见于后台权限矩阵 / 角色配置 / 标签分组。antd Table 原生 `expandable` + `childrenColumnName` 渲染的是缩进树（默认展开/折叠的父子嵌套），与这种「全展开 + 横向平铺 + 多选」的视觉效果完全不同。

OP 提供了多张截图说明期望效果，强调「好多后台都是这样设计展示，比较常见的需求」「自己手写还挺麻烦」。

## 复现 / 触发条件
- 现有 antd `<Table dataSource={treeData} rowSelection={...} expandable={{ defaultExpandAllRows: true }} />` 只能渲染缩进树。
- 期望效果（见截图）：父在第一列、子项在第二列起以 Tag/Chip 横向排列，每个子项独立 Checkbox；不是默认的「展开后子项也占整行」。

## 期望 vs 实际
- **期望**：Table 或 Tree 组件原生支持这种「平铺树形多选」样式。
- **实际**：antd 没有现成方案；用户必须用 `column.render` 手搓（合并单元格 + 受控 Checkbox + 自定义布局），UI「样式有点丑，用户体验不如截图那种」。

## 根因 / 关键讨论
- 一位回复者指出："看起来你就只是想用到 Table 的合并单元格功能。至于它看起来像一个树，这只是业务需求。自己计算并且用受控 checkbox 的方式控制就好了" —— 即 antd 认为这是渲染层 + 业务逻辑的问题，不打算内置。
- dosubot 给出常规可展开 `<Table rowSelection>` 示例（标准树形多选），但 OP 反馈「这个样式有点丑，用户体验不如我发的那种」。
- 维护者回复 "请勿询问如何使用的问题" —— 把 issue 转 discussion（Category: General, Labels: Usage）。
- 转 discussion 自 issue #53473。

## 对 data-grid 的启示
1. **差异化机会**：data-grid 可以把这种「树形平铺多选」做成开箱即用的 column renderer 或 expandable 样式 preset（如 `expandable.layout: 'inline-chips' | 'tree' | 'flat'`），直击本 discussion 痛点。
2. **合并单元格与树协同**：本仓已支持 rowSpan/colSpan + tree data，应验证「父行用 rowSpan 合并、子行用 colSpan 横向铺」这种组合是否能跑通，并补一个 demo。
3. **多选语义**：父子多选需要明确「选中父是否联动子 / 子全选是否勾父」的 `rowSelection.checkStrictly` 与这种平铺布局的协作（antd 默认 `checkStrictly: true` 会导致父子独立但视觉上还是树）。
4. **回归用例**：1k 个父节点 × 每个父 5 个子，渲染为平铺 chip 布局，断言布局正确、虚拟滚动正常、Checkbox 状态隔离。
5. **文档示例**：把这种「权限矩阵」UI 作为官方 demo（与 issue #37995 shouldCellUpdate 配合使用避免重渲染），是 antd 缺失、data-grid 有竞争力的方向。
