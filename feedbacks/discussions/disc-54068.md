# disc #54068 [RFC] Semantic Placement Naming Standardization

## 提案要点
RFC 提议在 antd 全组件库范围内**统一位置语义命名**：把 `position` / `*Position` 一律重命名为 `placement` / `*Placement`，与 Tooltip / Popover / Dropdown 等已用 `placement` 的组件保持一致。

- 现状梳理（提案正文里有完整表格）：
  - **使用 position 的组件**（待改）：Button `iconPosition`、Carousel `dotPosition`、Collapse `expandIconPosition`、List `pagination.position`、Modal `mousePosition`、Progress `gapPosition` / `percentPosition`、**Table `pagination.position`**、Tabs `position`、Timeline `items[number].position`。
  - **使用 placement 的组件**（不动）：Badge、Cascader、ColorPicker、DatePicker、Divider、Drawer、Dropdown、FloatButton、Mentions、Message、Notification、Popconfirm、Popover、Select、Slider、Steps、Tooltip、TreeSelect。
- 命名规范（节选）：
  - `Button.iconPosition` → `iconPlacement`（start | end，与 Collapse 一致）
  - `Carousel.dotPosition` → `dotPlacement`（top|left|right|bottom）
  - **`Table.pagination.position` → `pagination.placement`**（保持 `TablePaginationPosition[]` 类型）
  - `Tabs.position` → `tabPlacement`
  - `Timeline.items[n].position` → `items[n].placement`（兼容 RTL）
  - **例外**：`Modal.mousePosition`（绝对坐标）与 `Progress.percentPosition`（复合 align+type）保留原名。
- 迁移方案：minor 版双跑（新旧并存）+ `@deprecated` + dev `console.warn` + 联合类型 `Placement | LegacyPosition` + 文档迁移指南。

## 讨论
- 有参与者追问 "是否所有 left|right 都应转为语义化的 start|end？要考虑 RTL 吧？" —— 这是 RFC 的关键开放问题。
- 提案作者补 "position 和 placement 使用统计的内网链接不妥，要写到 GitHub"。提案随后被更新。
- afc163 参与（按任务描述），但具体回帖细节未在抓取范围内；讨论整体处于 RFC 收集意见阶段。

## 结论
RFC 处于**征求意见阶段**，无最终决议；倾向是接受 placement 统一化 + 双跑迁移。**Table `pagination.position` 是本仓直接相关项**。

## 对 data-grid 的启示
1. **直接采用 placement**：data-grid 一开始就用 `pagination.placement`（top|bottom|both），跳过 antd 的迁移期。本仓 docs-api 规约里就应明确：「位置类 prop 一律 `*Placement`，不用 `*Position`」。
2. **语义化取值**：尽量用 `start | end`（RTL 友好）替代 `left | right`；data-grid 内部布局是 CSS-Grid，配合 `direction: rtl` 与 logical properties（`inset-inline-start`）天然适配。
3. **例外项**：对鼠标坐标、绝对定位这类**绝对语义**保留 `position`/`coordinate` 命名，与「相对位置 placement」区分清楚 —— 与 RFC 例外列表保持一致。
4. **命名规约统一**：不仅 pagination，data-grid 的 `expandable.iconPlacement`、`filter.iconPlacement`、`sort.placement` 等都遵守此规范；并把这条规约写进 `JSDoc 封装清理法`（见 memory）的 category-pattern 校验里。
5. **避免迁移债**：data-grid 不背 antd 的历史包袱，可在 v1 就把 placement 标准立稳，作为新库的设计洁癖卖点。
6. 与 RFC #54633（统一标准化组件 Props 命名）配合阅读 —— 本条是它的子集（专攻 placement/position）。
