# disc #54633 [RFC] 统一且标准化组件 Props 命名

## 提案要点
RFC 作者「肝了一周」梳理 antd v5 所有组件的 Prop 命名混乱，提议借 **v6 大版本**作为破坏性更新的里程碑，把所有命名统一到 4 条规则：

1. **统一 size 取值**：`middle`/`default` → `medium`，全部组件统一为 `medium | small | large`（含 Pagination/Steps 等没 large 的组件）。
2. **统一 Render Prop 命名**：改为 `render + 功能名`（`renderItem`、`renderHeader`、`renderFooter`、`renderCell`），弃用 `itemRender` / `titleRender` 等旧风格。
3. **统一 boolean 命名**：`动作 + able`（`clearable`、`searchable`、`confirmable`、`droppable`）或 `[名词 +] 状态副词/形容词`（`disabled`、`readonly`、`loading`、`checkboxDisabled`）。`allowClear`→`clearable`、`showSearch`→`searchable`、`autoSize`→`autoResize`。
4. **统一事件命名**：`on + 状态 + 动作` 或 `on + 动作`；弃用 `onShowSizeChange`、`onChangeComplete`、`onFinish`（→`onSubmit`）、`onFinishFailed`（→`onError`）。

**Table 相关重命名（最关键，原文 37 节）：**
| 旧 | 新 |
|---|---|
| `size` | `large | medium | small` |
| `dataSource` | `data` |
| `title` | `renderHeader` |
| `footer` | `renderFooter` |
| `summary` | `renderSummary` |
| `onChange` | `onQueryChange`（明确表达「分页/筛选/排序查询条件变更」） |
| `expandable.expandedRowRender` | `expandable.renderExpandedRow` |
| `expandable.expandIcon` | `expandable.renderExpandIcon` |
| `expandable.expandRowByClick` | `expandable.expandRowOnClick` |
| `column.filterSearch` | （待讨论：filter+search 语义重复） |

其他高危项：`Button.type` 废弃（与 HTML 原生冲突）→ 用 variant+color；`Button.htmlType` → `type`；`Transfer.dataSource`→`items`；`Tree.treeData`→`data`；`TreeSelect` 全套去掉 `tree*` 前缀；`Modal.confirmLoading`→`okButtonLoading`；`Popconfirm.onConfirm`→`onOk`。

## 讨论
- **26 条评论、12 位参与者**，多数赞同；社区高度共识。
- 维护者引导到 wiki: `ant-design/ant-design/wiki/API-Naming-rules`（部分规则已落地，新代码已用 `xxxRender`）。
- 争议点：`disabled` 命名应 `subComponentDisabled`（被动语态形容词）还是 `disabledSubComponent`（名词词组）；OP 坚持前者更符合英语思维。
- `size`：有人建议 `medium`，有人建议 `default`（兼容性）；多数倾向 `medium`。
- 迁移工具：社区提议仿 `codemod-v5` 出 `codemod-v6`，OP 设想 `PropsRenamingTransformer` 配 JSON 规则表（AST 转换）。多次有人提到「让 AI/MCP 做」。
- 与 RFC #54068（placement/position）联动 —— 都属 v6 命名规范统一。
- OP 强烈反对 `@deprecated` 双跑：「会让属性又多又混乱，代码里 `||`/`??` 判断剧增，@deprecated 是下下策」，主张**借 v6 直接更替**。

## 结论
RFC 处于**广泛征询阶段**，社区高度共识但官方尚未承诺落地。可能作为 v6 一部分分阶段推进；每个组件单独开 PR。Table 是重灾区之一，变更项最多。

## 对 data-grid 的启示
1. **直接采纳全套规则**：data-grid v1 就按此 RFC 立 API，**不背 antd 历史包袱**。本仓 JSDoc 清理法 memory 已嵌入「category-pattern」校验，可扩展为「Prop 命名规则」校验。
2. **Table API 全部按新名**：
   - `<Table data={...} size="medium" renderHeader renderFooter renderSummary onQueryChange />`
   - `column.renderExpandedRow` / `renderExpandIcon` / `expandRowOnClick`
   - 弃用 `dataSource` / `title` / `footer` / `summary` / `onChange` 这些旧名 —— 直接用 RFC 新名。
3. **size 取 `medium`**：与 RFC 主流共识一致；不引入 `default`/`middle` 二选一的争议。
4. **bool 命名用 able 后缀**：`clearable`/`searchable`/`sortable`/`filterable`/`resizable`/`draggable`/`confirmable`；本仓 column 上的特性开关都遵守。
5. **render prop 用 renderXxx**：`renderCell`、`renderHeaderCell`、`renderFilterCell`、`renderSummaryCell`、`renderExpandIcon`。
6. **事件命名**：`onQueryChange`、`onRowClick`、`onCellClick`、`onSortChange`、`onFilterChange`、`onSelectChange`、`onExpand` —— 统一 `on + 名词 + 动作` / `on + 动作`。
7. **filterSearch 语义修订**：本仓 column 上的过滤搜索不沿用 antd 的 `filterSearch` 双关，改为 `filter.searchable` 子属性，消除 filter/search 重复。
8. **文档卖点**：写一篇「为什么 data-grid 的 API 比 antd v6 还干净」迁移指南，对齐此 RFC，吸引 antd 用户。
9. 与 disc #54068（placement RFC）合并遵循 —— 本仓 docs-api 规约里的「位置用 placement」直接落入此 RFC 的统一框架。
