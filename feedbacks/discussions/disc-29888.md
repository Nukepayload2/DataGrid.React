# disc #29888 table 分页之后如何能够获取全表数据？

## 现象
OP 使用 jQuery 在 DOM 上取 `<Table>` 的数据，发现开启分页后只能拿到当前页的 DOM 行。希望能拿到**全表数据**，特别是经过 filter 过滤之后的全量数据。

## 复现 / 触发条件
- antd `<Table pagination={{ ... }} dataSource={[...]} />`，开启分页。
- 用 jQuery 选择器（`$('#table-id tr')` 之类）只能拿到当前页 DOM。
- 翻页后 jQuery 取不到其它页 —— 因为分页是客户端渲染，未显示的页根本没挂到 DOM。

## 期望 vs 实际
- **期望**：分页后能获取「过滤后的全量数据」。
- **实际**：分页后只有当前页的 DOM；antd Table 没有直接暴露「全表数据（过滤/排序后）」的 API。

## 根因 / 关键讨论
- 另一位回复者追问 "什么需求需要这样做？"
- OP 回答："获取全表数据，特别是经过过滤之后的数据" —— 即 antd 的 filter 是在内部状态里维护的，外部拿不到过滤后的快照。
- 没有维护者给出官方方案；discussion 至今未答完。

## 对 data-grid 的启示
1. **暴露过滤/排序后的快照 API**：data-grid 应提供 `tableRef.getFilteredDataSource()` / `getSortedDataSource()` / `getVisibleDataSource()`，让外部能在分页/过滤/排序后拿到「真实数据视图」—— 这是 antd 长期缺失的能力。
2. **onChange 钩子**：在 `onChange(pagination, filters, sorter, extra)` 的 `extra` 里追加 `currentDataSource: T[]`（当前过滤+排序后的完整数据），方便业务方做「导出全表」「全选所有页」等场景。
3. **不要鼓励 DOM 取值**：在文档里明确警示「不要用 jQuery / querySelector 从 DOM 拿数据」—— antd 内部分页是 dataSource 切片，未渲染的行不存在于 DOM。data-grid 的虚拟滚动让这一点更严重（即便当前页也只渲染可见行）。
4. **回归用例**：分页 + filter + sorter 三者叠加时，`getFilteredDataSource()` 应返回排序前还是排序后？需要明确定义分层：`getRawData → getFilteredData → getSortedData → getPagedData` 四层 pipeline，每层独立可取。
5. 与本仓 docs-api 规约一致：把这组「数据视图 getter」加入公共 API 文档，并在 demo 中示范「导出过滤后的 CSV」用例。
