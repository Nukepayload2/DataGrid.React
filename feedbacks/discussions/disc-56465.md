# #56465 表格设置 scroll.y 之后如果把竖滚动条改成自动，右侧固定列会错位

## 现象
设置 `scroll={{ y: 400 }}` 后，即使数据很少也出现难看的竖滚动条。作者通过 CSS 强制把 `.ant-table-body` 的 `overflow-y` 改成 `auto`，结果右固定列（`fixed: 'right'`）的列头与数据区发生错位。

## 复现 / 触发条件
- antd ^6.1.3 / React 19.2。
- 三列各 `width: 450`，第三列 `fixed: 'right'`，5 行测试数据。
- `scroll={{ y: 400 }}` + `pagination={false}`。
- 外部 CSS：`.tableWrapper :global(.ant-table-body) { overflow-y: auto !important; }`。

## 期望 vs 实际
- 期望：右固定列列头与数据严格对齐。
- 实际：数据区右固定列比列头窄了一个滚动条宽度，发生水平错位。

## 根因 / 关键讨论
dosubot 给出官方解释：这是 antd Table 的**设计限制而非 bug**。设置 `scroll.y` 后组件会**始终为竖滚动条预留空间**，以同步固定列与主体内容的列宽对齐；用 CSS 把 `overflow-y` 改为 `auto` 会破坏内部同步滚动条宽度与列宽的逻辑，这种自定义方式不被官方支持。相关问题在 issue #54000 有说明。

作者进一步追问"动态行高 + 展开行 + 文本换行"的复杂场景。dosubot 指出此时**没有完美解法**，动态切换 `scroll.y`（undefined ↔ 数字）会引发死循环：高度变矮→滚动条消失→内容变宽→行高变高→滚动条又出现，并伴随 `rc-table` MeasureRow 异步测量列宽、`table-layout: auto` 回退、闪烁等问题。

## 对 data-grid 的启示
1. **不要预留滚动条宽度做对齐**：data-grid 改用 CSS Grid 后，固定列与主体共享同一套 column track（grid-template-columns），不存在 antd 那种"表头表体分两个 table 再用 scrollbar width 补偿"的结构，**理论上不会出现这种错位**。这是 CSS Grid 重做的一个重大结构性收益。
2. **支持 `overflow-y: auto` 语义**：用户业务诉求是"数据少时不显示滚动条"。data-grid 的 `ScrollContainer` 应当允许 auto/hidden/scroll 三态切换而不破坏列对齐，因为我们的对齐基准是 grid track 而非预留像素。
3. **避免动态 `scroll.y` 死循环**：用户提到动态切换 `scroll.y` 会引发高度震荡。data-grid 的虚拟化/非虚拟化两态切换也要警惕类似震荡——已有 `virtualization-toggle` 记忆，需保证切换平滑不闪烁。
4. **支持 `scroll.y: '100%'`**：用户期望表格自动撑满父容器高度。data-grid 应能接受百分比或 flex 高度，配合外层 flex 容器工作。
