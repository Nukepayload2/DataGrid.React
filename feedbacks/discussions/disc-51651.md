# #51651 scrollTo virtual=false 非虚拟跳转指定行仍导致页面滚动

## 现象
沿用 #46467 的相近场景：Table 在 `virtual={false}`（非虚拟列表）下，调用 `ref.scrollTo({ index: N })` 跳到指定行时，页面整体也会被滚动，而不只是表体内部滚动。

## 复现 / 触发条件
1. `<Table virtual={false} scroll={{ y: 300 }} ref={tableRef} />`；
2. 调用 `tableRef.current.scrollTo({ index: 50 })`；
3. 不仅表体滚到第 50 行，外层页面/祖先可滚动容器也被滚动。

复现 stackblitz：https://stackblitz.com/edit/react-ychcvz?file=demo.tsx

## 期望 vs 实际
- **期望**：scrollTo 只动表体。
- **实际**：表体和页面同步滚动。

## 根因 / 关键讨论
- 与 issue #46467 同源：底层 rc-table 用 `Element.scrollIntoView()` 实现非虚拟分支的滚动定位，浏览器规范使所有可滚动祖先一起滚。
- petercat 机器人提到了相关的 #28647（virtual table scroll to row），但未给方案。
- discussion 仅标 Q&A，无维护者正式回复——意味着问题至今未修。

## 对 data-grid 的启示
1. 这是 #46467 的姊妹问题，再次强化了"scrollTo 必须直接操作 scrollTop，禁用 scrollIntoView"的硬性约束。
2. data-grid 虚拟化和非虚拟化分支共用同一个 scrollTo 实现（基于 offsetTree 计算 targetTop，然后 `container.scrollTop = targetTop`），从架构上杜绝这种分支差异。
3. 验证矩阵：长页面 + 非虚拟 + scrollTo，断言 `document.documentElement.scrollTop` 不变，只有表体容器 scrollTop 变化。
4. 这种"基础 API 行为不一致"是组件库口碑杀手，data-grid 必须在 B5 阶段就把 scrollTo 当一等公民单测覆盖。
