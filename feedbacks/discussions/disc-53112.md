# disc #53112 [RFC] more semantic token for antd v6

## 提案要点
OP（arvinxx，antd 设计系统核心贡献者）认为现有 antd token 体系**换肤能力不够细致**：在 Claude Sonnet 3.7 辅助下，能做到 Winter/Monako/星空 主题这种「整体氛围换肤」，但要做 macOS / raycast 这种**带强设计辨识度**的还原，仍然不到位。

根因分析：现有背景层只分 3 级 ——
- `colorBgLayout`（页面布局背景）
- `colorBgContainer`（组件容器背景，卡片/表格/列表项）
- `colorBgElevated`（浮层背景，弹出菜单/对话框/tooltip）

`colorBgContainer` 和 `colorBgElevated` 是视觉层次的**关键决定因素**，但目前每层只有一个值，**没有梯度**，导致细粒度风格无法表达。

**提案**：为 bg 层级**增加二级、三级梯度选项**（如 `colorBgContainerSecondary`、`colorBgContainerTertiary`、`colorBgElevatedSecondary` 等），进一步提升系统灵活性。OP 预告「还有一些 case 需要增加 token 丰富度，待补充」。

## 验证方式（OP 建议）
v6 提供若干**官方主题包**：
- shadcn 主题包
- macOS 主题包

通过新增系列 token + 对应组件改造，证明换肤能力可达到这些设计语言的辨识度。

## 对 data-grid 的启示
1. **token 多级化**：data-grid 的 CSS var 体系应从一开始就规划**多级 bg 梯度**，例如：
   - `--dg-color-bg-layout` / `-secondary` / `-tertiary`
   - `--dg-color-bg-container` / `-secondary` / `-tertiary`（表头/表体/悬停/选中/斑马纹各占一级）
   - `--dg-color-bg-elevated` / `-secondary`（filter 下拉/编辑器气泡/Tooltip/拖拽预览）
   这正好契合本仓 demo-no-hardcoded-colors memory「全 token 化」的要求。
2. **本仓 theme-editor 卖点**：data-grid demo 门户的 theme-editor（memory: demo-portal-winui）可作为此 RFC 的实验场 —— 暴露多级 bg 梯度给用户调，能轻松换肤到 macOS / shadcn 风格，作为差异化对比 antd 的卖点。
3. **不要等 antd v6**：data-grid 现在 v1 就把多级 bg token 立稳，文档里可直接给「macOS 风 / raycast 风 / shadcn 风」三种主题预设。
4. **粒度警示**：梯度不是越多越好 —— OP 也只提「二级、三级」，太多 token 反而难管理。本仓可遵循 3 级上限（primary/secondary/tertiary），并在文档里画出层级语义图。
5. **与主题注入抄 antd memory 协同**：现在本仓用 `transformToken + realToken` 注入全套 `--ant-*`，未来 antd 加新 token 时，data-grid 的注入管线要同步扩展；可提前预留扩展点（动态收集 `--dg-color-bg-*` 系列并自动映射）。
6. **semantic token 命名规约**：本仓 token 命名应遵守「`semantic + level + modifier`」模式（如 `bg-container-secondary`、`text-secondary`），与本 RFC 的思路一致；写入 docs/api 规约。
