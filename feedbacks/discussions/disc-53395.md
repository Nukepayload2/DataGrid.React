# #53395 Table 组件的 scroll.y 属性自动适应当前屏幕高度的实现方式

## 现象
用户希望 `scroll.y` 不写死像素值，而是根据视口/父容器高度自适应，让 Table 的可滚动数据区域"合理填充"屏幕剩余空间（减去导航栏、页脚等固定元素）。

## 复现 / 触发条件
- 任何布局中需要 Table 自适应视口高度的中后台页面。
- 默认 antd Table 没有提供 `scroll.y: 'auto'` 或百分比形式的官方推荐方案。

## 期望 vs 实际
- 期望：组件内置或文档推荐一种"自适应高度"模式（如 `scroll.y: '100%'` 或 fill 模式）。
- 实际：官方未提供，需开发者用 JS 监听 resize 手动计算。

## 根因 / 关键讨论
petercat-assistant bot 给出方案：
1. 用 `window.innerHeight` 获取视口高度。
2. 减去固定元素（如 header 64px + footer 50px）。
3. 把计算结果 `setState` 后传入 `scroll={{ y: tableHeight }}`。
4. `useEffect` 中 `addEventListener('resize', handleResize)` 并在卸载时 `removeEventListener`。

代码示例就是经典的"手动 resize 测高"模式。社区目前没有官方 `scroll.y: 'auto'` 语义，用户必须用 JS 计算并 setState。

## 对 data-grid 的启示
1. **原生支持百分比/自适应高度**：data-grid 应在 `scroll.y` 中支持 `string` 类型（`'100%'`、`'fill'`），或提供独立的 `fill` / `autoHeight` prop，免去用户写 `useEffect + resize` 模板代码——这正是 antd 用户最大的痛点之一。
2. **flex 上下文自适应**：data-grid 的 `dg-wrapper` 可使用 `height: 100%` + `flex: 1` + 内部 `ScrollContainer` `flex: 1` + `overflow: auto`，让组件天然支持父容器 flex 自适应，无需 JS 监听 resize（`demo-compare-framework.md` 已约定 SplitDemo 用 flex）。
3. **官方文档需写明**：data-grid 文档中应明确给出"自适应高度"模式 demo（fill / 百分比），把 antd 用户最常踩的坑直接解决掉。
4. **联动虚拟化**：自适应高度 + 虚拟滚动是常见组合（视口高度决定可见行数 → 决定虚拟化窗口大小）。data-grid 的 `useRowHeightSystem` 应能消费"动态 scroll.y"而无需重渲染整个表格。
