# #54243 virtual 快速横向拖动滚动条后列表错位

## 现象
开启 `virtual` 后，**快速横向拖动自定义滚动条**（鼠标拖住 thumb 快速左右移动）会导致表头与表体列横向错位，列边界不再对齐；松手后有时能恢复，有时保持错位状态。

## 复现 / 触发条件
- antd Table + `virtual` + `scroll.x`
- 用鼠标按住虚拟横向滚动条的 thumb，快速拖动
- 触发条件：scrollbar 的 onScroll 事件与 rc-virtual-list 的渲染存在 race condition

## 期望 vs 实际
- 期望：任意拖拽速度下，表头与表体列始终对齐。
- 实际：快速拖动时表头与表体同步出现延迟，错位。

## 根因 / 关键讨论
- Dosu 判定：rc-virtual-list 渲染与 scroll 同步存在延迟/race condition；header 和 body 的 scroll 事件未完全原子同步。
- 提到的缓解措施（均治标不治本）：
  - 为所有列设置显式 `width`
  - `tableLayout="auto"`
  - 列宽之和 ≥ `scroll.x`
  - scroll 变化后强制 re-render
  - 升级 Chrome 136→137+（部分错位与浏览器渲染机制有关）
- 状态：`Unanswered`，无维护者回复、无 linked PR。

## 对 data-grid 的启示
此问题与 #45524 同源。data-grid 用 CSS Grid 共享列定义可从根本上避免——表头和表体的 `grid-template-columns` 必须由**同一份 columnTree 派生**，横向偏移由 grid 容器自身的 `scrollLeft`/`transform` 单点驱动，而非 header 和 body 各自维护独立的 scrollLeft 状态。必须做"快速拖拽 + 高频 onScroll 触发"的回归测试，确保在 rAF 合成帧之内表头与表体总是同步。
