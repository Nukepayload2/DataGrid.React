# disc #55876 Table 单元格编辑时候，select 如何联动

## 现象
表格行内编辑场景下，行内有两个 Select：name 与 age。期望用户选择 name 后，age Select 的 options 由 `getAgeApi(name)` 动态返回（如省市二级联动、客户/订单二级联动）。OP 提供了 StackBlitz 复现链接，问 antd 是否有官方方案。

## 复现 / 触发条件
- `<Table components={{ body: { cell: EditableCell } }} />`，可编辑行封装（常见社区样板）。
- EditableCell 里 `name` Select 与 `age` Select，两者 options 各自从 state 取。
- name 变化时希望触发 `getAgeApi(name).then(setAgeOptions)`，但**联动只在当前行生效**，不能污染其它行。

## 期望 vs 实际
- **期望**：antd 提供一等公民的「行内编辑 + 单元格联动」API，或官方示例覆盖异步 options 场景。
- **实际**：antd 只提供基础 EditableCell 样板，联动需要用户自己用 `Form.useWatch` + `form.setFieldsValue` 手搓，社区常踩坑（跨行污染、异步 options 不刷新、值不清空）。

## 根因 / 关键讨论
- dosubot 给出省市联动方案：在 EditableCell 内用 `Form.useWatch('province', form)` 监听父字段，父变化时 `form.setFieldsValue({ city: ... })` 重置子字段；options 通过 state 维护。
- 对异步 options（如 `getAgeApi`），dosubot 建议把 `useEffect([name])` 里调接口、`setAgeOptions` 存到当前行 state；推荐参考官方 `DebounceSelect` 与 issue #55872。
- 标签 `unconfirmed`、仅 1 个参与者；从 issue #55873 转为 discussion。

## 对 data-grid 的启示
1. **一等公民 API**：data-grid 应把「行内编辑 + 联动」做成内置能力 —— 提供 `column.editor` 抽象，内部用 `formContext` 把每行作为一个 sub-form，自动支持字段间依赖。这比 antd 的「EditableCell 完全自己写」要更易用。
2. **异步 options 标准模式**：`column.editor` 应支持 `options: (record) => Promise<Option[]>` 函数签名，data-grid 负责缓存 + 取消过期请求；并配合 `dependsOn: ['name']` 声明依赖字段，name 变化时自动重算 age 的 options 并清空 age 值。
3. **行级 state 隔离**：联动 options 必须**按行存储**，data-grid 应提供 `rowState` 容器（类似 Form.List 但作用在表格），避免 antd 社区常见的「行 A 改 name，行 B 的 age options 被污染」陷阱。
4. **回归用例**：1k 行 + 行内编辑 + province/city 联动；编辑行 A 的 province，断言行 B/C/D... 的 city options 不受影响。
5. **demo 示范**：在 docs 里写一个「省市联动 + 异步 options」完整 demo，直接对标本 discussion 的诉求，作为差异化卖点。
6. 与 issue #37995（shouldCellUpdate）呼应：联动重算应能配合 `shouldCellUpdate` 做行级 re-render 闸门，避免无关单元格被牵连重渲染。
